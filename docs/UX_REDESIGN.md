# 재미 중심 UX 개편

## 1. 분석과 분류

| 분류 | 적용 |
| --- | --- |
| 제거 | 난이도 선택/차등 계수, 생성 시 나이·성격·관심·병역 별도 입력, 개별 대학 결과 메일 열기 |
| 통합 | 학부 핵심 행동 5개, 대학원 상황별 행동 5개, 캐릭터/인간관계/기록 중심 메뉴 |
| 숨김 | OVR·연구/관계 수치·세부 활동·정산 상세·기존 전문연구 행정, 개발용 JSON 도구 |
| 자동화 | 적격 장학금 신청, 동의 후 부족액 대출/정산, 핵심 행동 뒤 성적 공개, 복무 반복 진행 |

세부 활동은 삭제하지 않습니다. 교환학생·대회 모집·선배 협업·졸업 프로젝트는 가능한 시기에
학기 화면에 안내하며 펼쳐서 선택합니다. 자동 대출은 금액과 조건을 표시한 버튼을 선택해야 적용합니다.

## 2. 저장과 호환

- 저장 버전 v13, 단일 키, 4슬롯 키와 컨테이너 형식은 그대로 유지합니다.
- `migrateSave`는 원본을 변경하지 않습니다. 이미 확정된 입시·채용·학위·평가를 다시 추첨하지 않습니다.
- easy/normal/hard 키는 이전 저장 읽기용으로만 남습니다. 모든 미래 계산은 기본 계수입니다.
- 신규 캐릭터만 `development.setup.militaryRule = "gender-v1"`로 새 일정 안내를 사용합니다.
  이전의 병역 대상 플래그·심사·연구 복무·복무 중 진행은 삭제하거나 소급 생성하지 않습니다.
- 여성 캐릭터에게는 새 입영 강제 이벤트를 발생시키지 않습니다.
  이전 저장의 진행 중 복무와 이력은 그대로 열어 완료할 수 있습니다.
- 모든 결과 난수는 실제 선택 시에만 사용합니다. UI 렌더링은 결과 재추첨을 하지 않습니다.
- 일반 화면에서는 JSON 기능을 숨깁니다. 개발/복구 도구는 `index.html?dev=1` 또는 사이트의 `?dev=1`로 엽니다.
- 작업 전 전체 백업을 저장소 외부에 만들고 ZIP 무결성을 검증했습니다.
  실제 방문자 브라우저 저장에는 접근하거나 수정하지 않았습니다.
- 사용자가 개편판에서 처음 저장할 때 슬롯 원본을 `:slots-v1:before-ux-v1`에 한 번 별도로 보관합니다.
  이 백업은 일반적인 `:previous`와 달리 후속 저장으로 덮어쓰지 않습니다.

## 3. 측정

동일한 Chromium, PC 1280px·모바일 375px. 선택지를 펼치기 전 기본 화면 비교입니다.
개별 원서 선택·전공 선택은 전후 공통이므로 지원 절차 클릭 수에서 제외합니다.

| 지표 | 기존 | 개편 |
| --- | ---: | ---: |
| 생성 입력/선택 | 9 | 4 |
| 기본 학기 화면 버튼 | 14 | 5 |
| 기본 기록 메뉴 summary | 10 | 2 |
| 대학 4곳 선택 후 제출→결과 비교 | 7클릭 | 2클릭 |
| 학기 초 정산→3행동·사건→방학→다음 학기 정산 화면 | 10클릭 | 7클릭 |
| 핵심 행동 3회 뒤 성적 공개 | 별도 1클릭 | 즉시 |
| 성적표→방학 행동 | 안내 화면 포함 2클릭 | 1클릭 |
| 일반 복무 시작 후 18개월 완료 | 분기 행동 6클릭 | 1클릭 |

14개와 5개는 버튼 수입니다. 2개는 접이식 메뉴 수로 서로 다른 지표입니다.
세부 화면까지의 총 기능 수를 줄였다는 뜻은 아닙니다.
학기 클릭 수는 자금 부족 상태에서 공부·연구·휴식, 사건 1회, 방학 휴식을 선택하는
동일 경로를 백업본과 개편본에서 실제 클릭해 측정했습니다. 기존은 부족액 대출·정산을
각각 선택하며 개편은 자동 신청·대출 동의·정산을 묶습니다. 다른 사건·관계 선택에 따라 클릭 수는 달라집니다.
인지 속도 “10초”는 설계 목표이며 실제 사용자 대상 시간 측정을 했다는 뜻은 아닙니다.

## 4. 피드백과 진행

- 대학 합격/불합격을 독립 결과 카드로 공개하고 장학금 감면과 다음 선택을 안내합니다.
- GPA 상승은 직전 학기 대비 변화와 다음 장학금 기회를 설명합니다.
- 입학·복무 완료·학위·입사·엔딩 등 중요 화면만 절제된 등장 효과로 강조합니다.
- `prefers-reduced-motion` 설정에서는 애니메이션을 사용하지 않습니다.
- NPC 친밀도/신뢰 계산과 실제 추천·협업은 유지하고 숫자는 상세로 옮겼습니다.
- 기본 행동은 기존 공부/연구/협업/근로/휴식 로직에 연결하며 새 보상을 중복 지급하지 않습니다.

## 5. 검증 범위

- 최종 `python3 run_all_tests.py`: **19개 테스트 파일 전체 통과**.
- 작업 전 배포본을 별도 디렉터리에서 전체 18개 테스트로 검증했습니다.
- 개편 테스트 `tests/test_ux.py`: 실제 생성·4곳 접수·전공 수정·중복 접수 방지·결과 재접속,
  남성 2학기 진행→입대 시점 선택→18개월 복무, 여성 2학기 진행·신규 입영 제외,
  이전 난이도 계수 통일·v13 순수 이전·렌더링 무변경·PC/모바일 폭을 확인합니다.
- 기존 테스트는 삭제된 생성 설정·메일 단계를 새 흐름에 맞추고 상세 메뉴를 펼치도록 변경합니다.
  특수 시작 나이·전공·이전 난이도 등은 UI 입력이 아니라 명시적 테스트 픽스처로 구성합니다.
- 장기 학부·석사·박사, 직장·창업, NPC 추천/연애, 복무 경로, 슬롯 충돌/복원,
  다섯 SSS 경로·40세·자유 종료/재개는 기존 회귀 테스트로 검증합니다.
- 결과와 전후 스크린샷은 `.artifacts/ux/`, 전체 테스트 결과는 `.artifacts/TEST_RESULTS.json`에 남깁니다.
- 추가 실플레이로 모바일에서 간소화된 5개 행동만 사용해 석사 4학기 학위를 완료했습니다.

## 6. 범위 밖과 한계

- 기존 코드에는 독립적인 NPC 자율 진로/라이벌 성장 시스템이 없습니다.
  실제 NPC 관계·추천·협업·팀 대회는 유지하지만, 없는 시스템을 구현된 것으로 표시하지 않습니다.
- 대학 모집은 기존 가상 통합 전형입니다. 수시/정시 별도 선발 회차를 새로 만들지는 않았습니다.
  전부 불합격하면 기존 재수/직업 교육/취업으로 이어집니다.
- 전문연구 복무의 박사 심사·전직 등 중요한 분기는 자동 진행이 멈추고 직접 선택하게 합니다.
- 브라우저별 저장이며 서버 계정 동기화는 없습니다.
